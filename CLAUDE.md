## Status

Early stage; Auth0 login and user sync (spec `.claude/specs/2_auth0-implementation.md`), the dashboard with course-outline generation (spec `.claude/specs/3_dashboard-ui.md`) and lesson content with the lesson page (spec `.claude/specs/5_content-creation.md`) are implemented. `client/` has the marketing landing page (`src/pages/LandingPage.jsx`, routed at `/` in `src/App.jsx`); the navbar has only "Demo" (opens the Warm Cream Demo Video modal, `src/components/LandingModals.jsx`) and "How it works" (links to the static `public/project_working.html`). The hero "Get started for free" calls `handleGetStarted`, which runs `loginWithRedirect` (or goes straight to `/dashboard` if already signed in); Auth0 callback errors show on the landing page. There are no custom login/sign-up forms; Auth0 Universal Login owns all of it.

The dashboard: `/dashboard`, `/courses/:courseId` and `/courses/:courseId/lessons/:lessonId` are children of one protected layout route (`src/layouts/DashboardLayout.jsx`, wrapped in `ProtectedRoute`). The layout calls `POST /api/users/sync` once, then mounts Chakra (dark-only) with a course-tree sidebar (a drawer below 768px), a top bar with the user menu, and the page. `pages/Dashboard.jsx` is just the Create Course form and Continue Learning cards; `pages/CoursePlaceholder.jsx` is a stand-in for the course page (`/courses/:courseId`), which is not built yet. After "Generate course" the app goes straight to Lesson 1 (temporary until the course page exists). State lives in `src/context/CoursesContext.jsx` (courses, lazily fetched outlines, a cache of ready lessons, tree expansion, optimistic progress via `setLessonCompleted` / `setCurrentLesson`; read it with `hooks/useCourses.js`). Components are in `src/components/dashboard/`.

The lesson page (`pages/LessonPage.jsx`, data from `hooks/useLesson.js`, components in `src/components/lesson/`): header, collapsible sections from the registry in `lessonSections.js` (Explanation, Quiz, Hinglish audio placeholder; a later session adds a section with one entry plus one component), and a footer with Mark as completed and Previous / Next. While a lesson is `pending` or `generating` the hook polls every 3 s (paused while the tab is hidden). `LessonRenderer` maps block types to components in `components/lesson/blocks/` and skips unknown types; AI text is parsed by `InlineText` (only `**bold**` and `` `code` ``, never HTML).

`server/` has the Express API: `GET /api/health`, `POST /api/users/sync`, `GET /api/users/me`, and the course routes under `/api/courses` (list, outline, create/generate, delete, progress `PATCH`, plus `GET /:courseId/lessons/:lessonId` and `POST /:courseId/lessons/:lessonId/retry`). Models: `User` (keyed on Auth0 `sub`), `Course` (owns `creator`, options and embedded lesson progress), `Module`, `Lesson`. Course creation calls Gemini for the outline; the lessons are then written in the background (see below). Not built yet: Side Quest, per-module YouTube videos, Hinglish audio and the course PDF (the Side Quest and Hinglish toggles are stored on the course; the outline prompt gets them as context only), and the course page. `landing_page/` at the repo root is the original standalone AI Studio export the landing page came from, kept for reference and not part of the app. Update this file as the real entry points and conventions land.

## Layout

Two independent npm packages (no root `package.json`, no workspaces). Run npm commands from inside each folder.

- `server/` — Express 5 + Mongoose API, ES modules (`"type": "module"`, so use `import`/`export` and include file extensions in relative imports).
  - Layered folders: `routes/` → `controllers/` → `services/` → `models/`, plus `middlewares/`, `utils/`, `config/`.
  - Auth: `express-oauth2-jwt-bearer` (Auth0-style JWT validation, needs audience and issuer base URL env vars).
  - LLM: `@google/genai` (Gemini) is the course-generation provider. `axios` is for outbound HTTP.
  - Config via `dotenv`: `config/env.js` loads `.env`, checks the seven required vars (`PORT`, `MONGODB_URI`, `AUTH0_ISSUER_BASE_URL`, `AUTH0_AUDIENCE`, `CLIENT_ORIGIN`, `GEMINI_API_KEY`, `GEMINI_MODEL`) and exits if any is missing. `GEMINI_FALLBACK_MODEL`, `LESSON_GEN_CONCURRENCY`, `LESSON_ATTEMPT_TIMEOUT_MS` and `LESSON_TOTAL_TIMEOUT_MS` are optional. `.env.example` exists; never edit `.env`.
  - Every error response is `{ message }`, produced by `middlewares/errorHandler.js` (it shows the message for statuses below 500 and for 502/503/504; other 5xx are generic). `app.js` builds the Express app (importable by tests); `server.js` connects to Mongo and listens.
  - Every course query is filtered by `creator` (the Auth0 `sub`); a course that isn't the caller's is a 404, never a 403. Constants shared with the client live in `utils/courseConstants.js` and must stay identical to `client/src/constants/course.js`.
  - Generation: `services/geminiClient.js` (`generateJson`) is the shared Gemini plumbing for outlines (`services/courseGenerationService.js`) and lessons (`services/lessonGenerationService.js`): up to 3 Gemini attempts (JSON schema) across `GEMINI_MODEL` then the optional `GEMINI_FALLBACK_MODEL`, 40s per attempt and 90s overall (504) for outlines, `LESSON_ATTEMPT_TIMEOUT_MS` (60s) and `LESSON_TOTAL_TIMEOUT_MS` (120s) for lessons. Busy/rate-limited/network failures that exhaust the attempts are a 503; bad or invalid output is a 502; a 400/401/403/404 from Gemini (wrong key or model name) is not retried on that model. Raw upstream messages are only logged, never sent to the client. A per-user in-memory lock (in `services/courseService.js`) returns 409 for a second concurrent generation; it only works for a single server process.
  - Lessons (`services/lessonQueue.js`): every lesson has a `status` (`pending` → `generating` → `ready` | `failed`). `ensureQueued(courseId)` (called after course creation, on every outline GET and every lesson GET) queues a course's pending lessons in module then lesson order; `prioritize` moves one the user is waiting on to the front; at most `LESSON_GEN_CONCURRENCY` (2) Gemini calls run at once, one lesson per course at a time; claiming is an atomic `findOneAndUpdate`, a failure marks only that lesson `failed` (only the user's Retry re-queues it), and `deleteCourse` calls `cancelCourse`. The queue is in memory, so like the 409 lock it only works for a single server process. `server.js` runs `recoverStaleLessons()` at boot: it gives lessons that predate the `status` field a `pending` status and resets `generating` lessons older than 3 minutes (`ensureQueued` does the same reset per course). Nothing is enqueued at boot. Lesson `content` is an array of typed blocks (see the spec), validated by `validateLessonContent`. Gemini returns separate `explanation` and `quiz` arrays (every explanation-block field is `required` in the schema, because lite models skip optional ones) and `toContent()` merges them into that array; the validator drops empty-body blocks and cuts questions beyond 5, but still needs a paragraph, an example and 4+ valid questions, and the reason for a rejected output is logged (never sent to the client). `lastError`, `videoQuery` and `attempts` are never sent to the client. `Module.video` / `Module.sideQuest` and `Lesson.audio` are reserved, `null`, for later sessions.
- `client/` — Vite 8 + React 19, JavaScript (JSX, no TypeScript).
  - Landing page styling uses **Tailwind CSS v4** (`@tailwindcss/vite` plugin in `vite.config.js`, `@import "tailwindcss"` in `src/index.css`). The landing page must not change when the dashboard is visited.
  - Dashboard UI: **Chakra UI v3** (not v2; v2 snippets like the `theme` prop, `Modal` and `useToast` don't apply). The system is in `src/theme/system.js` (`preflight: false`, and it neutralises Chakra's default `html` colors). The dashboard palette is defined once, as Tailwind theme values in `@theme static` in `src/index.css` (`--color-app-*`, matching the landing page's warm dark look with an orange accent, olive progress and brick-red brand); `system.js` maps Chakra tokens to those variables with `var(...)`, so don't hard-code hex in dashboard components. `colorPalette="accent"` is a custom Chakra palette built from the accent variable. Headings use the landing page's `--font-heading` with `letterSpacing="tight"`; the sidebar shows the landing page's "AI-Powered Course Generator ✳" wordmark; primary actions use `components/dashboard/PillButton.jsx` (white pill, brand-colored text, → arrow). `ChakraProvider` is mounted only inside `DashboardLayout`, not in `main.jsx`, and the layout puts `.dark` on `<html>` while mounted so portaled menus, dialogs and the drawer are dark too. Toasts use `components/dashboard/toaster.js` + `AppToaster.jsx`. No icon package; icons are inline SVGs in `components/dashboard/icons.jsx`.
  - Chakra gotchas found here: `Field.Root` ignores `ids`, so set `id` instead; the `RadioCard` border and checked state are on `Item`, not `ItemControl`; the `progressbar` role is on `Progress.Track`, so give the label there; `SkipNavLink` takes `id` (its target), not `href`; Menu `onSelect` goes on `Menu.Root` and receives `{ value }`.
  - Routing: `react-router-dom` v7. Auth: `@auth0/auth0-react`, provider in `src/context/Auth0ProviderWithNavigate.jsx` (inside `BrowserRouter`). API calls go through `src/utils/api.js` (`apiRequest`).
  - `html2canvas` + `jspdf` are for exporting generated course content to PDF in the browser.
  - `vite.config.js` proxies `/api` to `http://localhost:5000` in dev.

## Commands

Client (`cd client`):
- `npm run dev` — Vite dev server
- `npm run build` / `npm run preview`
- `npm run lint` — oxlint (not ESLint)

Server (`cd server`):
- `npm run dev` — `node --watch server.js`; `npm run start` — `node server.js`.
- `npm test` runs Vitest (`vitest.config.js` sets dummy env vars). Tests are in `server/tests/`: supertest against `app.js`, `checkJwt` and the Gemini services mocked (`courses.test.js` and `lessons.test.js` also mock `lessonQueue.js`; `lessonQueue.test.js` runs the real queue with a mocked lesson generator), Mongo via `mongodb-memory-server` (the first run downloads a `mongod` binary). Single file: `npx vitest run tests/courses.test.js`; single test: add `-t "name"`.
- `nodemon` was removed (it pulled in a `minimatch` advisory); use `node --watch`.
